# 항해 기록 작성·추가 가이드

이 사이트는 정적 창작 기록을 읽는 PWA입니다. 대화가 자동 저장되거나 ChatGPT 메모리와 동기화되는 기능은 없습니다.
다음 대화에서 설정을 이어가려면 독자가 항해 요약을 복사하거나 정전 메모를 직접 전달해야 합니다.
새 장면은 JSON/그림을 편집하고 테스트·PR 검토·승인 후 사이트 업데이트로 게시합니다.

## 기존 기록과 컬렉션

`app.js`의 `MARIE_DIARIES` 10개와 출력 순서는 이 컬렉션과 분리되어 있습니다. 새 항해 기록을 그 배열에 넣지 않습니다.
`data/voyage_entries.json`에는 `AST2-VOYAGE-001`, `V001-01`~`V001-12`가 제공 자료의 순서·본문 그대로 있습니다.
이미 발행한 ID를 다른 장면에 재사용하지 않습니다. 과거 일기를 새 항해의 DAY 001과 한 타임라인으로 정렬하지 않습니다.

새 권은 예를 들어 다음처럼 추가합니다.

- `data/voyage-002/entries.json`: `schema_version: 1`, `collection_id: AST2-VOYAGE-002`, 제목·기록 속 day·world·ship·layer와 `entries` 배열.
- `assets/voyage-002/`: 최적화 WebP 커버와 장면. 경로는 `assets/voyage-숫자3자리/영문숫자_파일명.webp` 형식입니다.
- `data/voyage-002/CANON_MEMORY.md`: 그 권 시점의 정전. 001의 메모를 최신 시점으로 덮어쓰지 않습니다.
- 이미지 목록/출처/alt/크기를 별도 메타데이터에 기록합니다. 참고용 생성 보드·원본 대용량 파일은 게시하지 않습니다.
- `data/voyage_collections.json`의 `collections` 배열에 권을 등록합니다. `source`, `cover`, `cover_alt`, `synopsis`, `canon`, `additional_scenes`, `snapshot` 구조는 기존 001을 참고합니다.

등록 권이 둘 이상이면 읽기 화면에 권 선택 드롭다운이 나타납니다. 목록의 첫 권이 기본값이며 작성자가 순서를 정합니다.
기록 카드의 순서는 각 JSON 배열 순서입니다. 시간순 정렬/기존 일기와 병합을 수행하지 않습니다.
렌더러는 특정한 12편에 고정되지 않으며 새 권의 길이로 카드·카운터·이전/다음을 구성합니다.

## 기록 항목

```json
{
  "id": "V002-01",
  "day": "DAY 002",
  "time": "08:20",
  "scene_time_is_approximate": true,
  "title": "새로운 장면의 제목",
  "category": "관측",
  "image": "assets/voyage-002/01_scene.webp",
  "alt": "그림 내용을 설명하는 짧고 구체적인 대체 텍스트",
  "summary": "카드에서 읽을 짧은 소개. 인물의 비밀을 앞질러 폭로하지 않습니다.",
  "body": "[DAY 002 / 기록]\n본문.\n\n“마리의 대사.”\n\n(마리의 내면.)"
}
```

시각은 00:00~23:59 형식입니다. 임의 구성한 시각은 `scene_time_is_approximate: true`로 표시합니다.
UI는 이를 `대략`으로 읽습니다. day/time은 기록 속 날짜이며 사용자의 현지 시각이나 선실의 라이브 시뮬레이션 시간과 무관합니다.
본문은 빈 줄로 문단을 나누고 대사 다음에 괄호 속 내면을 둡니다. 괄호를 제거하지 않습니다.
괄호 문단에는 별도 시각 스타일을 적용하고, 모든 텍스트를 `textContent`로 넣습니다. 임의 HTML/스크립트는 지원하지 않습니다.

## 정전과 불확실성

001의 정전 원본은 `data/CANON_MEMORY.md`입니다. 001의 고정 스냅샷은 DAY 001 약 14:31, Layer 0입니다.
이야기의 마지막 항목은 **대략 14:35**이지만, 고정 상태 요약은 원본 정전의 마지막 확인 시각을 유지합니다.
잔여 2,056,560 km, 가정 속도 12 km/s, 예상 약 47시간 36분은 가상 예비 관측·일정 속도 가정입니다.
선체 12.8m, 최초 240만 km±40만 km도 이번 에피소드에서 도입한 이야기 수치이며 라이브 센서/공식 추진 제원으로 게시하지 않습니다.

UNKNOWN-001의 인공성, 광원/송신원의 동일성, 스쿨드 연구소와 창고의 연결은 미확정입니다.
전파 침묵·수동관측을 유지하고 아직 접촉/착륙/구조가 일어나지 않은 시점입니다. 새 근거 없이 확정하지 않습니다.

인물의 비밀은 작가 정전과 독자가 선택해 읽는 내면에만 둡니다. 공개 시놉시스·카드 소개·alt·인게임 대사에서 갑자기 폭로하지 않습니다.
완전한 정전 메모는 UI의 스포일러 안내를 펼친 뒤 다운로드합니다. 기본 복사 요약은 항로·불확실성 중심입니다.
실제 사용자 기억·개인정보·대화 전문·토큰은 자료에 추가하지 않습니다.

## 캐시와 검증

새 권의 JSON, 이미지, 메모 파일을 `sw.js`의 `ASSETS`에 추가하고 VERSION을 올립니다.
HTML/JS/데이터/이미지가 같은 버전으로 준비된 뒤에만 새 worker가 설치되도록 전체 프리캐시를 사용합니다.
`pwa.js`의 승인 기반 업데이트를 유지합니다. 설치·첫 온라인 캐싱이 끝나면 오프라인에서도 읽을 수 있습니다.

- `npm test`: 스키마/ID/순서/본문/기존 일기 불변/캐시와 기존 게임 규칙.
- `python tests/voyage-browser-qa.py`: 실제 읽기·테마·모바일·오류 복구·v05→현재 PWA/오프라인.
- `python tests/rooms-browser-qa.py`, `python tests/browser-qa.py`: 방 이벤트 전체·기존 비행 회귀.
- 새 권의 데이터/시각을 검토하고 필요한 고정 fixture/예상 개수 검사를 갱신합니다. 없는 lint/build 도구를 통과했다고 기록하지 않습니다.
- 실기기 검증과 브라우저 에뮬레이션을 구분하고 PR에 캡처·출처·용량·미검증 조건을 기재합니다.

main 직접 push·병합·운영 배포 대신 작업 브랜치와 검토 가능한 PR을 사용합니다.
